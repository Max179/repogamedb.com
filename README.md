# repogamedb.com

A source-only static site for the game **R.E.P.O.** (build 0.4.0), published at
<https://repogamedb.com>. Pages are generated by a small Node builder from a normalized data index that is
committed to this repository. There is no framework, database or runtime service: the deploy target is a folder of
HTML, CSS, SVG and image files.

The output has two deliberately separate layers:

- **Player layer** — home, game guide, entity hub and entity pages, guides, tools and updates. These are the pages
  a player is meant to find.
- **Evidence layer** — class, field, enum and value tables plus provenance, under `/reference/` and `/entity/` and
  marked `noindex`. These pages exist so a claim can be checked, not to rank in search.

## Requirements

- **Node.js 22+** (the publish workflow uses Node 22). Build, tests and gates need no third-party packages.
- **Python 3** only for optional image tooling (`tools/image-sanity.py`, `tools/extract-images.py`), not for the
  build.
- No access to the game, no credentials and no network are needed to build or test the committed tree.

## Preview

```sh
npm run build
python3 -m http.server 4205 --directory web/dist
# open http://127.0.0.1:4205/
```

`npm run build` writes `web/dist/`, which is generated output and is not tracked by git. A Node-only alternative
is `node tools/preview.mjs` (port 4187 by default, override with `PORT`).

## Commands

| Command | What it does |
| --- | --- |
| `npm run build` | Regenerate `web/dist/` from `data/normalized/p0-inventory.json`. |
| `npm test` | Run the site test suite (`tests/site.test.mjs`). Builds into a temp directory and checks routes, canonical URLs, noindex/sitemap policy, provenance, images and content invariants. |
| `npm run gates` | Content gate (`tools/content-gate.mjs`) then image coverage (`tools/image-coverage.mjs`). Fails on a bad entry, an unattributed image or an entry without a picture. Writes `reports/image-coverage.md`. |
| `npm run preflight` | Publish checklist: runs the tests, requires a clean working tree, re-runs both gates, checks `reports/status.json`, the handoff report, the workflow, the untracked raw/build boundaries and the coverage floor. |
| `npm run smoke` | Check the built artefact in `web/dist` against the classified URL list (`config/urls.json`). With a URL argument (`npm run smoke -- https://repogamedb.com`) it checks the live site instead. |
| `npm run status` | Recompute `reports/status.json` from a fresh temp build plus git. |
| `npm run typecheck` | `tsc --noEmit -p tsconfig.ci.json` — checks `.mjs` and the `.ts` pipeline. |
| `npm run verify` | `npm test && npm run typecheck && npm run preflight` — the full local gate chain. It expects a clean tree, so run it after committing. Preflight runs both gates in no-write mode, so the tree stays clean. |

Typecheck (TypeScript is a devDependency; covers `.mjs` and `.ts`):

```sh
npm install
npm run typecheck
```

`node_modules/` is ignored and must not be committed. The build and tests do not need it.

## Repository layout

| Path | Contents |
| --- | --- |
| `pipeline/` | Site generator (`site.mjs`), status generator, and the extraction/decoder scripts used on the Windows host (metadata reader, serialized-file readers, UnityPy probes, value normalizer). |
| `tests/` | `site.test.mjs` — deterministic site and data-integrity tests. |
| `tools/` | Content and image gates, preflight, smoke test, URL classifier, coverage matrix, preview server, image extractors and manifest writer. |
| `content/` | The site's editorial source: `published/` entries, `articles/` guides, `draft/`, `images-manifest.json` (the image licence/provenance ledger), and `assets/`, `images/`, `renders/` pictures. |
| `data/normalized/` | The committed, normalized data index that the build reads (`p0-inventory.json`, `p0-instances.json`, `repo-object-names.json`, header samples, localization tables). |
| `data/raw/` | The unpacked game package on the extraction host. **Not tracked** and never needed to build. |
| `web/` | Static shell assets (`web/assets/`) and the generated site (`web/dist/`, ignored). |
| `config/` | URL classification (`urls.json`) and the coverage floor (`coverage.json`). |
| `reports/` | Generated and audit reports: coverage, image coverage and reviews, status, verification, publish plan, data boundary. |
| `docs/` | Design spec and `data-pipeline.md` (how the normalized data was produced and why it is not reproducible on a clean Mac clone). |
| `.github/workflows/publish.yml` | CI gate job and Cloudflare Pages deploy job. |

## Data boundary

- **Raw game files are not in git.** `data/raw/` is ignored; nothing under it is tracked. The repository ships only
  the normalized index, so a clean clone can build, test and gate the site without the game.
- **Regenerating the data requires Windows.** The extractors read a local `R.E.P.O. v0.4.0` install
  (`REPO_Data/`, `Managed/Assembly-CSharp.dll`, level/shared asset files) and the extraction scripts contain
  hard-coded Windows paths for that host. They also need Python 3.12 with UnityPy (for the Unity object table and
  payload dumps) while the schema decoder is the repository's own .NET/ECMA-335 metadata reader.
- **Therefore the normalized data is not reproducible on a clean Mac clone.** The committed indexes are the build
  input; re-extraction is a separate, host-specific step. This is a known and documented residual gap — see
  [`docs/data-pipeline.md`](docs/data-pipeline.md) and [`reports/data-boundary.md`](reports/data-boundary.md) for
  the exact paths, tool versions, byte-level anchors and open decoder work.
- **No game bytes are committed.** The intermediate payload dumps (`data/normalized/*-payloads.json`) are ignored,
  and the raw package is excluded from the deploy artefact.

The version documented on the site is the one the game itself carries (0.4.0); the evidence anchors and SHA-256
hashes are recorded in `docs/data-pipeline.md` and `reports/data-boundary.md`.

## Images and licensing

The MIT licence in [`LICENSE`](LICENSE) covers the **site code only**. It does not relicense any game asset or
third-party/community picture:

- **Game assets** (textures, renders and screenshots exported from the game) are the property of the developer and
  their rights holders. They are used only to identify the subject they belong to, and they keep their original
  status.
- **Community images** from the R.E.P.O. Fandom wiki are **CC-BY-SA 4.0**, by their respective authors. Every such
  file is recorded in `content/images-manifest.json` with source page, author, licence, licence URL and retrieval
  date, and credited on the page that uses it and on [/credits.html](https://repogamedb.com/credits.html). Files
  whose exact source page could not be recorded are marked as weak provenance in
  [`reports/image-sources.md`](reports/image-sources.md).
- **Original diagrams** were drawn for this site and are labelled as diagrams, never as screenshots.

The build's content gate refuses a community picture without attribution, a diagram presented as a screenshot, or a
published entry without a picture. If you are a rights holder and want an image removed, use the contact address on
the site.

## Deploy

The canonical publish procedure, current blockers and exact commands are in
[`reports/publish-plan.md`](reports/publish-plan.md). In short: `.github/workflows/publish.yml` runs the gates and
then deploys `web/dist` to the Cloudflare Pages project `repogamedb-com` on a push to `main`.

- CI gate job: build → site tests → typecheck.
- Deploy job (after the gate): build → `tools/preflight.mjs` → `tools/smoke.mjs` → `wrangler pages deploy`.
- DNS and custom-domain changes are dashboard actions, not part of the workflow.

## Secrets

The repository contains **no credentials, tokens or private keys**. Deployment uses the
`CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` GitHub repository secrets, which are injected at deploy time
and never written to a tracked file. Do not commit a token, an account ID or a local `.env`; `preflight`
checks that the workflow uses a secret rather than a literal token.
